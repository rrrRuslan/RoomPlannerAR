# Architecture Decision Records

Кожне архітектурне рішення — окремий файл `ADR-xxx-<slug>.md`. Пише `architect`, апрувить техлід. Змінювати стек можна лише новим ADR.

| ADR | Рішення | Статус |
| --- | --- | --- |
| ADR-001 | Монорепозиторій для всіх компонентів | Прийнято, файл ще не написано |
| ADR-002 | Contract-first: OpenAPI як єдине джерело правди, клієнти генеруються | Прийнято, файл ще не написано |
| ADR-003 | Бекенд на Kotlin + Spring Boot | Запропоновано, підтвердити |
| ADR-004 | Два мобільні клієнти: нативний Android і Flutter від одного контракту | Прийнято, файл ще не написано |
| ADR-005 | Агентна розробка в Claude Code, людина апрувить кожен merge | Прийнято, файл ще не написано |
| ADR-006 | Стратегія сканування кімнати на Android | Після технічного spike |
| ADR-007 | Новий незалежний продукт; старий iOS-додаток — лише референс | Прийнято, файл ще не написано |
| ADR-008 | Специфікації й зміни ведуться в OpenSpec | Прийнято, файл ще не написано |
