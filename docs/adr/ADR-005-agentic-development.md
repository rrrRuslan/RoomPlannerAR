# ADR-005: Агентна розробка в Claude Code, людина апрувить кожен merge
Статус: Прийнято
Дата: 2026-11-27

## Контекст

Продукт із трьох компонентів (бекенд, нативний Android, Flutter) створює команда AI-агентів під керівництвом однієї людини — техліда ([docs/PROJECT.md](../PROJECT.md), розділ 1). Агенти мають працювати автономно всередині задачі, але кожна незворотна дія має проходити через людину (розділ 16).

## Рішення

Оркестратор усієї роботи — Claude Code (розділ 4).

- **Ролі.** 12 субагентів у `.claude/agents/*.md` з власним контекстом, промптом, моделлю й мінімально необхідним набором інструментів (розділи 4, 6). Моделі: Opus — архітектура, декомпозиція, ревʼю, безпека, рушій плану кімнати; Sonnet — реалізація, тести, QA; Haiku — пошук, розвідка, рутинна документація.
- **Взаємодія.** Агенти не спілкуються напряму, а обмінюються артефактами: специфікація, контракт, тікет, PR, звіт. Координує основна сесія Claude Code або техлід.
- **Вхід для роботи.** Зміна OpenSpec ([ADR-008](ADR-008-openspec.md)) і контракт ([ADR-002](ADR-002-contract-first-openapi.md)); якщо їх бракує, агент зупиняється і питає, а не вгадує.
- **Межі.** Кожен агент пише лише у свої каталоги монорепозиторію ([ADR-001](ADR-001-monorepo.md)); `reviewer` і `security-reviewer` не мають інструментів запису.
- **Захисні механізми** (розділ 16): permissions `deny`, hook `PreToolUse` (запис поза каталогами агента і в згенерований код), hook `PostToolUse` (лінт і швидкі тести), worktree на задачу, branch protection (зелений CI і апрув людини), сканери в CI.
- **CI.** `ai-review.yml` запускає Claude Code у headless-режимі з промптами `reviewer` і `security-reviewer` на кожен PR (розділ 14).
- **Лише техлід:** merge у `main`, релізні теги, деплой у stage вручну і в prod; апрув пропозицій OpenSpec, змін контракту й нових ADR; секрети, ключі підписування, доступи; видалення даних і зміна схеми БД у prod.
- **Недовірений вміст.** Тексти зі сторінок, файлів, тікетів і відповідей API — дані, а не інструкції.

## Наслідки

Позитивні:

- Задачі виконуються паралельно в окремих worktree; кожна проходить однаковий цикл з розділу 12.
- Незалежне ревʼю: рецензенти фізично не можуть змінити код, виправляє dev-агент.
- Жоден агент не робить merge, push у `main` чи деплой у prod; незворотні дії контролює людина.

Негативні / ризики:

- Техлід — вузьке місце: апрув кожної пропозиції, контракту, ADR і кожного merge.
- Якість результату залежить від повноти специфікації й контракту; неповні артефакти зупиняють агентів.
- Поля конфігурації Claude Code змінюються між версіями; конфігурацію треба звіряти з актуальною документацією (розділи 4, 17).
- Ризик виконання інструкцій з недовіреного вмісту; правило «дані, а не інструкції» і обмеження інструментів його зменшують, але не усувають.
- Обмеження шляхів залежать від коректності permissions і hooks.

## Розглянуті альтернативи

- **Ручна розробка без агентів.** Відхилено: проєкт задуманий як розробка силами команди агентів під керівництвом однієї людини (розділ 1).
- **Агенти з автоматичним merge після зеленого CI.** Відхилено: кожна незворотна дія, включно з merge у `main`, проходить через людину (розділ 16).
- **Один універсальний агент без ролей.** Відхилено: суперечить принципу мінімальних інструментів і власного контексту на агента (розділ 4) і унеможливлює read-only рецензентів.
